# 产品经理核心术语表（工程师友好版）

很多产品与商业黑话听起来玄乎，其实底层逻辑与软件工程、分布式系统和网络通信高度相通。本表按场景分类，并用**工程师熟悉的技术概念进行精准类比**，帮你实现一秒映射。

---

## 一、 战略与产品文档类

| 英文缩写 / 术语 | 中文名称 | 一句话产品释义 | 工程师技术概念类比 |
| :--- | :--- | :--- | :--- |
| **BRD** | 商业需求文档 (Business Requirements Document) | 向高管申请预算和立项的文档，重点讲市场规模、投入产出比（ROI）和商业模式 | 架构立项 RFC 提案中的 `Motivation & Cost Estimation` 章节 |
| **MRD** | 市场需求文档 (Market Requirements Document) | 分析目标市场、竞品格局、目标客户群体及产品定位的文档 | 系统选型调研报告（对比 Kafka vs NSQ vs Pulsar 的适用场景） |
| **PRD** | 产品需求文档 (Product Requirements Document) | 详细定义产品功能逻辑、交互流程、异常边界与验收标准的规格书 | 接口协议规范（Protobuf `.proto` 定义 + 状态机流转说明 + SLA 规范） |
| **MVP** | 最小可行性产品 (Minimum Viable Product) | 刚好能验证核心商业/用户假设的最小功能集合，绝不多写一行冗余代码 | 验证架构可行性的 **PoC (Proof of Concept)** 最小原型 |
| **PMF** | 产品市场契合度 (Product-Market Fit) | 产品精准击中了目标市场痛点，用户留存稳固且开始自发口碑传播的状态 | 系统压测通过、线上流量自然涌入且负载稳定收敛的健康态 |
| **GTM** | 市场进入策略 (Go-To-Market) | 产品开发完成后，如何定价、通过什么渠道、用什么话术推向目标客户的完整打法 | 软件包编译打包完成后的 **CI/CD 发布、镜像分发与节点推广策略** |
| **USP** | 独特卖点 (Unique Selling Proposition) | 客户为什么选你而不选竞品的核心差异化理由 | 框架的核心 Benchmark 优势（如零拷贝、无锁队列带来的 10 倍吞吐提升） |
| **Dogfooding** | 吃自己的狗粮 (内部试用) | 团队自己在日常工作中真实高频使用自家开发的产品，第一时间发现体验痛点 | 编译器团队用自己写的编译器编译下一代编译器（**自举 Bootstrapping**） |

## 二、 用户研究与体验设计类

| 英文缩写 / 术语 | 中文名称 | 一句话产品释义 | 工程师技术概念类比 |
| :--- | :--- | :--- | :--- |
| **Persona** | 用户画像 | 抽象出来的典型目标用户代表（包含背景、习惯、核心痛点、使用场景） | 压测时构造的**典型流量模型 (Traffic Profile)**（如高频读低频写型客户端） |
| **JTBD** | 待办任务理论 (Jobs-To-Be-Done) | 用户不是为了买产品，而是雇佣产品在特定场景下帮他完成某项具体任务 | **接口契约 (Interface)**：调用方不关心底层实现，只关心输入参数能否返回预期结果 |
| **Aha Moment** | 顿悟时刻 / 惊喜时刻 | 新用户首次在产品中切身感受到核心价值、决定留下来继续用的关键瞬间 | TCP 三次握手成功完成、建立起稳定长连接的那一刻 |
| **TTFV** | 首次价值体验时间 (Time to First Value) | 新用户从注册进入产品，到首次跑通核心流程拿到结果所耗费的时长 | 开源项目从 `git clone` 到跑通第一个 `Hello World` 的耗时（越短越好） |
| **Happy Path** | 正常主流程 | 用户完全按照设计预期、没有任何报错或网络异常走完的理想路径 | 代码中的正常执行分支（无 `err != nil`、无超时的主干逻辑） |
| **Edge Case** | 边界场景 / 极端情况 | 弱网、空数据、并发冲突、超长文本、无权限等非典型但必须处理的场景 | 单元测试里的**边界值测试（空指针、溢出、并发竞态 Race Condition）** |
| **Cognitive Load** | 认知负荷 | 用户理解当前界面、做出下一步操作所需消耗的脑力成本 | CPU 执行复杂分支预测失败时的上下文切换开销（越低系统越丝滑） |
| **Onboarding** | 新手引导与激活 | 帮助新用户快速熟悉产品、跨越冷启动门槛的引导流程 | 集群新节点的 **Bootstrap 初始化与配置预热流程** |

## 三、 数据指标与商业化类

| 英文缩写 / 术语 | 中文名称 | 一句话产品释义 | 工程师技术概念类比 |
| :--- | :--- | :--- | :--- |
| **North Star Metric** | 北极星指标 | 衡量产品核心价值交付与长期健康度的唯一最顶层指标 | 分布式系统的顶层核心 SLA 指标（如整体有效请求吞吐量 Goodput） |
| **Guardrail Metric** | 护栏指标 / 反向指标 | 做增长或改版时绝不能突破的安全底线指标（如崩溃率、退订率、延迟） | 性能优化时的 **内存上限 / P99 延迟熔断阈值（Circuit Breaker）** |
| **DAU / MAU** | 日活跃 / 月活跃用户数 | 单日或单月内产生有效核心行为的去重用户数 | 每日/每月活跃并发连接客户端数（Active Connections） |
| **Stickiness** | 用户粘性 (`DAU / MAU`) | 比值越高说明用户每个月回访的天数越多、依赖度越强 | 连接复用率（Keep-Alive 长连接占比） |
| **Retention** | 留存率（次留/7留/30留） | 第 N 天后仍然继续回来使用产品的用户比例 | 缓存命中率（Cache Hit Ratio）随时间的衰减曲线 |
| **Churn Rate** | 流失率 | 停止使用产品或取消订阅付费的客户比例 | 连接断开超时被回收的比例 |
| **Funnel** | 转化漏斗 | 用户从第一步到最终目标步步衰减的转化路径 | 多级流水线（Pipeline）每一级的过滤率与丢包率诊断 |
| **Cohort** | 同期群 | 按同一时间段注册或同一特征分组的用户群，用于纵向追踪真实留存 | 按相同版本号（Version Tag）打标的灰度流量批次监控 |
| **LTV** | 生命周期总价值 (Lifetime Value) | 一个客户在从开始使用到彻底流失的整个周期内，为公司贡献的毛利总和 | 单条长连接在存活周期内传输的有效业务载荷总量 |
| **CAC** | 客户获取成本 (Customer Acquisition Cost) | 市场与销售花掉的费用平摊到每成功转化一个新付费客户身上的成本 | 建立一次加密连接所需的握手计算与带宽开销（需要 `LTV > 3 × CAC` 才划算） |
| **ARPU** | 每用户平均收入 (Average Revenue Per User) | 总营收除以活跃或付费用户数，衡量单客变现能力 | 单工作协程平均处理的价值吞吐量 |
| **ROI** | 投入产出比 (Return on Investment) | 投入的资源成本与收回的商业收益之比 | 硬件扩容成本 vs 带来的 QPS 提升性价比 |
| **NPS** | 净推荐值 (Net Promoter Score) | 调查用户“有多大意愿向朋友推荐本产品”，推荐者比例减去贬损者比例 | 开源项目的真实口碑（自发 Star 与生产环境采用率 vs 吐槽 Issue 比例） |

## 四、 敏捷研发与项目管理类

| 英文缩写 / 术语 | 中文名称 | 一句话产品释义 | 工程师技术概念类比 |
| :--- | :--- | :--- | :--- |
| **Epic** | 史诗故事（大型需求模块） | 跨多个迭代周期的宏大功能主题，需要拆分为多个 User Story | 大型架构重构专项（需拆分为多个 PR 和里程碑） |
| **User Story** | 用户故事 | 以“作为[某角色]，我想要[某功能]，以便[获得某价值]”格式描述的最小交付单元 | 一个可独立合入、可独立测试验证的 Feature PR |
| **AC** | 验收标准 (Acceptance Criteria) | 明确列出满足哪些条件才算这个 User Story 开发完成 | 单元测试的 `Assert` 断言集合（全部绿灯才算通过） |
| **Backlog** | 待办需求池 | 所有待开发需求、优化项、技术债的有序优先级队列 | 消息队列中按优先级排序的待消费 Task Queue |
| **Scope Creep** | 需求蔓延 | 开发过程中不断塞入临时小需求，导致工期无限拖延失控 | 内存泄漏（Memory Leak）或无限制膨胀的依赖树 |
| **Feature Flag** | 特性开关 | 代码已合入主干部署上线，但通过远端配置动态控制对哪些用户开放 | 线上动态配置中心（etcd / Apollo）控制的灰度路由开关 |
| **A/B Testing** | A/B 对照实验 | 将同质流量随机分流到旧版（对照组）与新版（实验组），用统计学检验改动是否真的有效 | 生产环境双版本金丝雀对比测试（Canary Benchmarking） |
| **UAT** | 用户验收测试 (User Acceptance Testing) | 上线前由 PM 或真实业务代表从端到端体验角度进行的最终走查 | 生产发布前的端到端集成冒烟测试（E2E Smoke Test） |
