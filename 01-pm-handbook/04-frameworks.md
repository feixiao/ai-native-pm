# 产品经理常用方法论框架速查

就像软件工程有 23 种设计模式（Design Patterns）来解决特定架构问题一样，产品管理也有一套成熟的分析与决策框架。遇到具体业务卡点时，直接查表套用对应框架，能让你的思考既全面又有说服力。

---

## 一、 用户研究与需求挖掘类

### 1. JTBD (Jobs-To-Be-Done，任务理论)
* **一句话解释**：用户并不是想买你的“产品”，而是“雇佣（Hire）”你的产品帮他在特定情境下完成某项任务。
* **适用场景**：挖掘底层真实需求、跳出同质化功能内卷、寻找真正的跨界竞品。
* **操作公式**：
  > **当我在 `[特定情境 When...]` 时，我想要 `[完成什么任务/动机 I want to...]`，以便于我能 `[达成什么理想结果 So I can...]`。**
* **实战案例（以音视频会议为例）**：
  * *错误（功能视角）*：用户需要一个“AI 实时生成会议字幕”功能。
  * *正确（JTBD 视角）*：**当我在**通勤路上环境嘈杂不便戴耳机开周会时，**我想要**实时看清每个人发言的核心结论与点名我的事项，**以便于我能**不错过关键任务且不被发现心不在焉。

### 2. 5-Whys (五问根因分析法)
* **一句话解释**：像排查线上 Core Dump 故障一样，连续追问 5 次“为什么”，穿透表面现象直达业务本质。
* **适用场景**：客户提出奇葩定制需求、线上转化率突然下跌时。
* **实战案例**：
  1. **客户诉求**：“我要你们在后台加一个‘一键导出全部历史音视频通话明细 CSV’的按钮。”
  2. *Why 1（为什么要导出 CSV？）* → “因为我要放进 Excel 里算每个坐席每天的有效通话时长。”
  3. *Why 2（为什么要算有效通话时长？）* → “因为月底要给外包坐席团队结算绩效工资。”
  4. *Why 3（为什么现有报表不能直接用于结算？）* → “因为现有报表把 5 秒以内的未接通/秒挂电话也算进去了。”
  5. **结论（真实需求）**：客户根本不需要每天手动导出几百兆的 CSV，只需要在现有报表上增加一个 **“过滤通话时长 > X 秒（有效通话）”** 的筛选项即可，开发量从 3 天降为 1 小时。

### 3. 用户画像 (Persona) 与 角色卡片
* **一句话解释**：将目标用户群抽象为具象的典型代表，防止产品设计沦为“自嗨”。
* **适用场景**：新产品立项、团队对“到底优先服务谁”产生分歧时。
* **核心要素（B 端/技术产品必分两类人）**：
  * **采购决策者 (Buyer / 老板)**：关心价格、合规安全、ROI、同行标杆案例。
  * **实际使用者 (End User / 一线开发者或运营)**：关心接入文档清不清楚、报错好不好排查、用起来顺不顺手。

### 4. 用户旅程地图 (User Journey Map)
* **一句话解释**：像分布式链路追踪（OpenTracing）一样，把用户从接触产品到完成目标的每一步动作、情绪高低点、卡点画在一条时间轴上。
* **适用场景**：优化新用户首次接入体验（Onboarding）、降低激活流失率。
* **关键步骤**：按阶段拆解动作 → 标注每个节点的“痛点/摩擦点（Friction）” → 找到情绪最低谷（Aha Moment 之前的流失重灾区）并针对性优化。

## 二、 需求优先级排序类

### 5. RICE 评分模型
* **一句话解释**：用四个量化维度给需求算总分，彻底终结“谁嗓门大听谁的”排期争吵。
* **计算公式**：
  $$\text{RICE Score} = \frac{\text{Reach (触达人数)} \times \text{Impact (影响程度)} \times \text{Confidence (把握度)}}{\text{Effort (研发人月成本)}}$$
* **参数评分标准**：
  * **Reach**：一个周期内预计影响多少真实用户？（填具体数字，如 5,000 人/月）
  * **Impact**：对单个用户的价值有多大？（3 = 巨大提升，2 = 高，1 = 中，0.5 = 低，0.25 = 微小）
  * **Confidence**：你的数据和推论有多大把握？（100% = 有明确数据支撑，80% = 中等把握，50% = 纯拍脑袋猜测）
  * **Effort**：需要消耗多少研发+设计+测试人周/人月？

### 6. Kano 模型 (卡诺模型)
* **一句话解释**：将产品功能按“具备程度”与“用户满意度”的关系分为 4 类，指导资源分配。
* **四类属性**：
  1. **必备属性 (Must-be / 基础型)**：做好了用户觉得理所应当，做不好直接卸载或退费（如：音视频通话不能断线、账单不能算错）。**→ 策略：守住底线，达标即可，不必过度投入。**
  2. **期望属性 (One-dimensional / 线性型)**：做得越好，用户越满意（如：清晰度越高越好、延迟越低越好、价格越便宜越好）。**→ 策略：核心竞争力战场，紧盯竞品保持领先。**
  3. **魅力属性 (Attractive / 兴奋型)**：不做用户不会怪你，但一旦做出来会让用户惊艳并主动传播（如：开会迟到进入时自动私聊推送前 10 分钟 AI 摘要）。**→ 策略：低成本打造 1-2 个差异化亮点（Aha Moment）。**
  4. **无差异属性 (Indifferent)**：做不做用户根本不在乎（如：后台设置页面换了一套酷炫的 3D 动效图标）。**→ 策略：坚决砍掉！**

### 7. MoSCoW 法则
* **一句话解释**：针对单一版本发布范围（Scope）的快速裁剪工具，防止版本延期。
* **四级划分**：
  * **M - Must have**：没有它本次发版就毫无意义或违法合规（P0 阻塞级）。
  * **S - Should have**：重要但非致命，如果排期实在不够，可以通过临时绕行方案（Workaround）顶替（P1）。
  * **C - Could have**：锦上添花，有空余工时就顺手做了（P2）。
  * **W - Won't have (this time)**：明确宣布本期不做，放入下期需求池，管理好各方预期。

## 三、 产品战略与增长指标类

### 8. 北极星指标 (North Star Metric, NSM)
* **一句话解释**：全公司或整个产品线唯一最核心的成功衡量指标，代表“用户从产品中真正获得了核心价值”。
* **好北极星指标的 3 个标准**：
  1. 能反映用户真正获得了价值（而不只是虚荣曝光）；
  2. 是长期商业营收的领先指标（Leading Indicator）；
  3. 团队每个人的日常工作都能拆解并影响到它。
* **经典案例**：
  * **Zoom / RTC 平台**：每周高质量（无卡顿投诉）托管会议总分钟数。
  * **Slack / 协作工具**：日活团队中发送消息超过 2000 条的深度活跃团队数。
  * **Spotify**：用户每日有效收听总时长。

### 9. AARRR 海盗增长模型
* **一句话解释**：用户全生命周期漏斗的 5 个核心阶段，像排查网络丢包一样定位增长卡点。
* **五层拆解**：
  1. **Acquisition（获取）**：用户从哪来？（关注：渠道曝光、CPC/CPA 获客成本）
  2. **Activation（激活）**：用户是否首次体验到了产品核心价值（Aha Moment）？（关注：新用户首日跑通核心流程比例、TTFV 首次价值时间）
  3. **Retention（留存）**：用户还会回来吗？（关注：次留、7 日留存、30 日留存、Churn 流失率）
  4. **Revenue（变现）**：如何从用户身上赚到钱？（关注：付费转化率、ARPU 单用户平均收入、LTV 生命周期总价值）
  5. **Referral（自传播）**：用户愿意推荐给朋友或同事吗？（关注：NPS 净推荐值、K-Factor 病毒传播系数）

### 10. MVP (Minimum Viable Product，最小可行性产品)
* **一句话解释**：用最小成本构建一个能跑通完整“价值验证闭环”的产品形态，核心目的是**低成本证伪假设**。
* **工程师最易犯的 MVP 误区**：
  * *错误做法*：要造一辆车，V1 先造四个轮子（不能开），V2 造底盘（不能开），V3 造车身，V4 才能开上路。
  * *正确做法*：V1 先给用户一块滑板（能代步，验证用户确实有短途出行需求）→ V2 滑板车 → V3 自行车 → V4 汽车。

## 四、 数据分析与实验决策类

### 11. 漏斗分析 (Funnel Analysis)
* **一句话解释**：衡量多步骤流程中每一步的转化率与流失率，找到投入产出比最高的优化环节。
* **实战举例（开发者平台接入漏斗）**：
  `访问官网 (100%)` → `注册账号 (40%)` → `创建应用获取 AppID (35%)` → `下载 SDK 并跑通首通音视频通话 (8%)` → `正式上线付费 (5%)`。
  * *一眼看出瓶颈*：从“获取 AppID”到“跑通首通通话”流失了近 80% 的开发者！此时 PM 最该做的不是去改官网注册页面，而是立即去优化 SDK 快速入门文档、提供一键可运行的 Demo 工程。

### 12. 同期群分析 (Cohort Analysis)
* **一句话解释**：按用户首次注册/激活的时间分组（如 10 月第一周注册的用户群），纵向观察他们随时间推移的留存变化，剥离“新增买量掩盖老用户流失”的假象。
* **判断 PMF 的黄金法则**：如果不同批次用户的留存曲线在一段时间后最终趋于水平（不再继续跌向 0%），说明产品已经找到了稳固的核心价值（达成 PMF）。
