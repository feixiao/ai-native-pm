# AI 辅助快速原型与交互验证

过去，产品经理画原型只有两条路：要么用 Axure / 墨刀拖拽出灰扑扑的静态线框图（业务方和客户看着毫无体感），要么排期苦等 UI 设计师出高保真 Figma 图（动辄耗费三五天）。

在 AI 时代，**“可点击运行的高保真前端代码原型 (Vibe Prototyping)” 正在全面取代传统的静态线框图**。结合你的技术底子，用自然语言驱动 AI 在 15 分钟内搓出一个带真实交互状态、甚至能接 Mock 数据的 Web Demo，是你在团队内部和客户面前最震撼的武器。

---

| 工具名称 | 核心能力与定位 | 最佳适用场景 |
| :--- | :--- | :--- |
| **Claude Artifacts** | 对话框右侧实时渲染 React + Tailwind + Lucide 图标组件，支持即时多轮交互修改 | **首选轻量神器**：10 分钟内为单个功能模块、弹窗交互、数据仪表盘生成可点击原型 |

## 二、 为什么“可交互原型”比“万字长文 PRD”更管用？

1. **一图胜千言，一动胜万言**：
   你在 PRD 里写 800 字描述“当音视频网络丢包率超过 20% 时，右上角信号格变黄并弹出弱网切换音频模式提示条，3 秒后自动收起”，研发和老板看完脑子里的画面完全不一样；但你用 Claude Artifacts 花 3 分钟生成一个带模拟“切换网络状态”按钮的动态网页，会上演示 10 秒钟，全员瞬间达成 100% 共识。
2. **前置暴露交互死角**：
   只有在自己亲手点击原型的过程中，你才会猛然发现：“哎，用户点完这个按钮之后怎么返回上一步？”“列表为空的时候这片区域怎么空荡荡的？”

## 三、 四步极速原型工作流 (15 分钟 SOP)

```
[Step 1: 梳理信息层级] ──► [Step 2: 生成主干交互] ──► [Step 3: 注入状态切换器] ──► [Step 4: 嵌入评审演示]
 列出页面核心目标与数据项     用 Claude / v0 生成首版     加入顶部"调试栏"模拟空状态/报错    开会现场实时点击走查
```

> **核心秘籍 —— 永远在原型顶部加一个「PM 状态调试栏 (Debug State Switcher)」**：
> 让 AI 在原型页面最上方做一个灰色的小工具条，包含几个切换按钮：`[正常有数据态]`、`[首次进入空状态]`、`[加载中 Skeleton]`、`[弱网报错异常态]`、`[配额耗尽锁定态]`。评审会上你每点一下切换按钮，研发和 QA 就能直观看到每种边界状态下的 UI 表现！

## 四、 即插即用提示词模板库 (Prompt Templates)

### 模板 1：生成带「多状态调试栏」的高保真可交互原型（必用神级模板！）
```markdown
你是一位顶尖的 SaaS 产品设计师与 React 前端专家。请帮我使用 React + Tailwind CSS + Lucide Icons 构建一个可交互的高保真产品原型。

### 业务场景与页面目标
我们要设计【页面名称，如：实时音视频云控制台的「通话质量实时监控与诊断中心」】。
目标用户是【用户角色】，他来到这个页面的核心任务是【核心任务，如：在 10 秒内定位某通正在进行的卡顿通话是由于客户端弱网还是服务端转发延迟引起的】。

### 页面核心布局与功能模块
1. **顶部检索与概览区**：支持按 RoomID / UserID 搜索，展示当前在线房间数、全网健康度评分、异常告警数。
2. **主内容区（左右分栏或上下结构）**：
   - 【模块 A 描述，如：端到端链路拓扑图（发送端 → SFU 节点 → 接收端）】
   - 【模块 B 描述，如：实时码率/丢包率/抖动双轴折线图及关键事件时间轴】
3. **关键交互动作**：点击某个异常节点时，右侧滑出抽屉展示详细诊断建议与一键下发降级策略按钮。

### 关键要求（极其重要！）
请在页面最顶部固定放置一个深色背景的 **「PM 评审状态切换调试栏 (Prototype State Switcher)」**，让我可以在演示时一键切换以下 4 种页面状态：
- `Normal (正常通话态)`：展示健康的模拟数据与绿色指标；
- `Weak Network Alert (弱网高丢包告警态)`：高亮标红丢包节点，弹出 AI 根因诊断提示条；
- `Empty State (首次使用空状态)`：展示友好的引导插画与“如何接入首个房间”快捷入口；
- `Loading / Error (接口超时异常态)`：展示骨架屏或重试引导。

要求视觉风格现代、克制（类似 Linear / Vercel / Stripe 风格），所有按钮和 Tab 均可真实点击切换。
```

### 模板 2：将文字版 PRD 直接转化为可点击的多步向导流程 (Wizard Flow)
```markdown
以下是我的 PRD 中关于【多步骤流程名称，如：新建 AI 语音客服 Agent 并绑定 SIP 电话中继】的文字描述：
<prd_flow>
[粘贴 PRD 中的步骤说明]
</prd_flow>

请将这段文字转化为一个可真实走通的 **多步骤向导式交互原型（Step-by-Step Wizard）**：
1. 包含顶部步骤进度条（Step 1 → Step 2 → Step 3 → 完成激活）。
2. 每一步都要有真实的表单输入校验反馈、默认值预填（Smart Defaults）以及右侧实时预览效果。
3. 提供「上一步」、「下一步」以及「保存草稿」交互，并在最后一步展示成功庆祝页（Aha Moment）与快速测试入口。
```

### 模板 3：用 Mermaid 代码快速生成复杂业务时序图与状态机
```markdown
请根据以下业务逻辑，帮我生成两张可直接嵌入 Markdown PRD 的 Mermaid 图表代码块：
业务逻辑：【描述业务，例如：客户端发起连麦申请 → 主播端收到弹窗（15秒倒计时） → 主播同意/拒绝/超时未响应 → 服务端信令下发与推拉流建立 → 连麦异常中断后的重连与销毁】

请输出：
1. **Mermaid 完整时序图 (`sequenceDiagram`)**：包含观众端、服务端信令、媒体服务器(SFU)、主播端四个参与者，清晰标出正常流程、`alt` 分支（拒绝/超时）及异常恢复。
2. **Mermaid 状态机图 (`stateDiagram-v2`)**：聚焦“连麦会话状态”的完整生命周期转换，标注每个箭头的触发事件与超时阈值。
```

### 模板 4：迭代微调现有原型的可用性与减少认知负荷
```markdown
请审视当前这个原型组件的信息密度与交互路径。
假设现在使用它的用户是一个【完全不懂底层技术名词的普通运营人员】，请帮我对当前界面进行「可用性降维重构」：
1. **隐藏技术复杂性**：将界面上暴露的专业参数（如采样率、帧率、编码格式）折叠进「高级设置」，主界面只保留面向业务场景的 3 个预设档位卡片（带直观图标和一句话适用场景说明）。
2. **视觉层级强化**：确保全屏只有 1 个最醒目的主行动按钮（Primary CTA），弱化次要操作。
3. 直接输出重构后的完整可运行代码。
```
