# 独立开发者 AI-Native PM 工作流与实战 Prompt 模板库

> **核心哲学**：大厂 PM 靠写文档在组织中求取共识；独立开发 PM 靠 AI 驱动在欲望中做最小刀法切片。
> 本指南提供从**点子过滤 ──► 过去事实取证 ──► 一页 MVP 契约 ──► Prompt-to-Spec 代码转译 ──► 单周决策门**的全流程实战 Prompt 模板与操作手册。

## 二、 Stage 1：选题过滤与过去事实取证 (Evidence Gate)

### 1.1 核心逻辑与门禁
* **核心心智**：坚决不问“如果做出来你会用吗”这类礼貌假阳性问题；只拷问用户**过去 30 天内曾为该问题付出过的真实时间、金钱与痛苦代价**。
* **准入门禁**：必须达到 **Level 2（存在痛苦事实与笨拙替代方案）** 才准立项。只有自嗨猜想（Level 0）或客套点赞（Level 1）时，严禁写任何一行代码！

### 1.2 实战 Prompt 1：个人现实约束过滤与机会卡生成
```markdown
你现在是我的【冷血商业合伙人兼 CFO】。我的背景是一名独立全栈工程师，我脑子里蹦出了一个产品点子。
请严格依据独立开发者的资源限制，用最挑剔、理性的眼光对我进行“个人现实约束审查”。

我的点子描述：
[在此处用 1~3 句话描述你的产品点子，例如：帮跨境自由职业者自动将混乱的中文日常笔记整理为规范的英文交付周报]

我的个人现状：
- 每周稳定可用时间：[例如：10 小时]
- 可触达的种子用户群体：[例如：微信里有 2 个海外接单自由职业者社群，约 400 人]
- 技术与行业长板：[例如：熟练掌握 React/Node/Tailwind，有 3 年跨境远程工作经验]
- 风险偏好：[例如：可接受 3 个月零收入，但不接受 7x24 实时客服，不接受高危隐私合规]

请按以下格式输出《机会卡》并给出冷血裁决：
1. **目标客群 (ICP)**：具体定位到具体角色，绝不写“所有人”。
2. **触发场景 (Trigger)**：问题发生的具体时刻。
3. **用户当前笨拙替代方案 (Workarounds)**：他们现在用什么 Excel、手动复制或脚本凑合？
4. **单人交付与维护负担**：评估客服支持、第三方 API 费用及数据合规风险。
5. **首版明确排除 (Non-Goals)**：列出本阶段坚决不做的 3 项大功能。
6. **裁决建议**：[🟢 值得推进 / 🟡 缩小客群 / 🔴 立即扼杀（给出无情理由）]
```

### 1.3 实战 Prompt 2：《The Mom Test》事实证据提炼与定级
```markdown
你现在是我的【AI 苛刻需求审查官】。我刚刚和潜在用户进行了一次沟通（或者我在社交媒体/论坛收集了一批反馈）。
请依据《The Mom Test》原则，帮我彻底剥离其中的“假阳性礼貌客套”，提取“过去发生的真实事实”。

输入的内容（访谈记录/聊天截图文字/社区抱怨）：
"""
[粘贴你与用户的真实对话、微信聊天记录或 Reddit/V2EX 帖子]
"""

请按以下框架进行事实提炼与证据定级：
1. **剔除无价值信息**：标出所有假设性赞美（如“如果做了我会买”、“想法很酷”），并说明为何不可信。
2. **提取过去事实证据**：
   - 用户过去是否曾主动寻找过替代工具？具体用了什么？
   - 用户上一次遇到该痛点是什么时候？造成了什么具体损失（耗时/被罚款/客户投诉）？
   - 用户是否曾为解决此问题掏过哪怕 1 分钱？
3. **证据级别裁决 (Level 0~4)**：
   - Level 0 (自嗨猜想) / Level 1 (礼貌赞美) / Level 2 (痛苦事实) / Level 3 (行为承诺/押金) / Level 4 (重复付费)
4. **结论与下一步行动**：
   - 若低于 Level 2：强制命令我停止写代码，并给出 2 个继续追问过去事实的问题。
   - 若达到 Level 2+：准许进入《一页 MVP 契约》阶段。
```

## 三、 Stage 2：极窄刀法与一页 MVP 契约 (Thin-Slice Contract)

### 2.1 核心逻辑与门禁
* **核心心智**：大厂做产品讲究“完整闭环（横向积木）”，独立开发讲究“纵向单条通路（垂直薄切片）”。
* **严苛戒律**：首版坚决不做用户注册登录、坚决不做可视化管理后台、坚决不做多端同步；首版交付物必须严格控制在 **一页纸内**，并白纸黑字写死 **14 天两周止损死线（Drop-dead Date）**。

### 2.2 实战 Prompt 3：一页 MVP 契约生成器
```markdown
你现在是我的【架构极简切片师】。我已经拿到了该痛点的真实事实证据（Level 2+）。
现在我准备动手开发 V1.0，但我极容易陷入“功能膨胀”和“大架构自嗨”。
请用无情的刀法砍掉 70% 的周边需求，为我生成一份《一页 MVP 契约》。

项目背景与核心价值：
[简要描述你准备解决的单一问题]

请严格按以下模板输出，篇幅不得超过一页纸（控制在 600 字以内）：

# [产品名] V1.0 MVP 契约

## 1. 狭窄闭环 (Single Vertical Slice)
- **只服务**: [极度具体的细分人群]
- **触发时刻**: [具体发生场景]
- **核心输入**: [用户需要提供什么，如粘贴一段凌乱文本]
- **核心输出**: [系统生成的唯一确定性结果，如一个干净的 Markdown 文件]
- **价值确认**: [用户做了什么动作代表问题被解决，如一键复制发给客户]

## 2. 绝对不做清单 (Non-Goals / 坚决围栏)
- [ ] 坚决不做 1: 用户系统与密码找回（首版先用 LocalStorage / Magic Link 存储）
- [ ] 坚决不做 2: 可视化后台大盘（先用飞书表格/Google Sheet 导出）
- [ ] 坚决不做 3: 任何超过 1 种输入格式的兼容支持

## 3. 验证指标与防破产护栏
- **核心成功行为**: [如：首周有 5 个去重用户完成核心转换并导出]
- **防破产限额**: 单用户每日限流 [N] 次，API 支出月度预算上限 [$50]

## 4. 两周冷血止损条件 (Drop-dead Gate)
- **复查死线**: [立项日期起严格加 14 天，填入具体 YYYY-MM-DD]
- **停止条件**: 若到期未达到 [核心指标]，立即无条件归档删库，绝不追加工时！
```

## 四、 Stage 3：Prompt-to-Spec 代码生成器就绪规格

### 3.1 核心逻辑与技术栈铁律
独立开发者的产品文档**不需要向任何人汇报，而是直接投喂给 Claude Code、Cursor Composer、Aider 或 Codex 进行全自动代码生成**。  
PM 文档必须降维编译为：**包含确定性技术栈约束、端侧限流防破产护栏与零歧义验收断言的 Task Spec**。

#### ⚠️ 致命陷阱：为什么绝不能使用通用泛化的技术栈？
大多数独立开发者在驱动 Coding Agent 时，会任由 AI 自由选型。而大模型默认偏好 Web 领域的流行套件（如 Node.js / Express / Next.js / Prisma / Redis / Docker）。
**如果这个技术栈脱离了开发者本人的底层核心长板**：
1. **丧失代码审计与排障能力**：一旦线上出现并发竞态、异步死锁或内存泄漏，开发者无法在一分钟内肉眼定位，彻底沦为 AI 偶发 Bug 的“人肉修补匠”；
2. **环境与依赖地狱拖垮节奏**：引入不熟悉的包管理器、构建工具与多容器中间件，单人排障时间呈指数级上升；
3. **放弃了十年积累的“不公平技术优势”**：独立开发者唯一能打败大团队的武器，就是利用自己在熟悉底层栈上的极高生产力与调优直觉。

因此：**Coding Agent 规格的第一步，必须白纸黑字锁死技术栈围栏与绝对禁飞区！**

## 五、 Stage 4：单周单问题冲刺与冷血决策门

### 5.1 核心逻辑
* 迭代期间拒绝同时推进“UI优化、加新功能、SEO优化”。**每周全精力只验证一个核心不确定性（1-Problem Sprint）**。
* 周末对照 14 天两周止损线，由 AI 扮演冷血裁判进行五选一裁决，及时止损。

### 5.2 实战 Prompt 5：周末决策门复盘与冷血裁决
```markdown
你现在是我的【冷血商业裁判】。我是一名独立开发者，我的产品 V1.0 已经交付并提供给种子用户试用了 1 周。
现在是周末复盘时刻。请拒绝任何安慰与自我感动，严格用数据和用户行为为我做出生杀裁决。

本周既定假设：
[例如：新用户在没有我指导的情况下，能否在 3 分钟内自助生成第一份周报]

本周实际发生的数据与事实：
- 触达/看到页面的用户数：[例如：35 人]
- 尝试输入内容的用户数：[例如：8 人]
- 真正完成输出并导出的去重用户数：[例如：3 人]
- 用户主动反馈与原话：[例如：2 个人抱怨英文表达太官方，1 个人问能不能支持飞书]
- 距离 14 天止损死线还剩：[例如：7 天]
- 本周消耗的个人工时与 API 费用：[例如：工时 8 小时，API 费用 $4.2]
```

## 六、 独立开发者 11 维红队避坑军规 (Red-Team Audit)

在执行上述任何阶段前，随时可调用 AI 进行 **11 维红队压力排雷**：

| 风险维度 | 红队致命质询 | 强制低成本化解对策 |
| :--- | :--- | :--- |
| **1. 没人需要** | 过去 30 天内，有谁曾主动在网上发帖抱怨此问题或寻求替代工具？证据在哪？ | 停写代码；先去 Reddit/Twitter/V2EX 找到 3 个具体抱怨案例并私信回访。 |
| **2. 专家自嗨** | 是不是只有你这个技术专家才会这样操作？普通人能否在 30 秒内理解？ | 找完全不懂技术的非目标朋友看一页纸 Demo，测试能否复述核心用途。 |
| **3. 缺乏分发** | 第一批 20 个种子用户怎么来？如果在已知渠道发帖没人理，备用抓手是什么？ | 放弃广撒网投放；找准目标人群已存在的微信群、Discord 或竞品差评区定点触达。 |
| **4. 架构过载** | 为什么非要引入 Redis/微服务/K8s？能否用单个 SQLite + 静态托管在一台廉价 VPS 上跑满前半年？ | 强行降级技术选型，单机完成 MVP 验证。 |
| **5. 价格落空** | 用户赞赏你的功能，但真的有人掏出信用卡预付吗？ | 在官网放真实支付/Stripe 预购按钮，测试真实支付意愿（未完成退款）。 |
| **6. 支持拖垮** | 每个用户遇到 Bug 是否都需要你远程 Debug 半小时？你顶得住 50 个用户同时发邮件吗？ | 核心错误必须有自助重置与清晰提示，砍掉一切不可控的黑盒外部依赖。 |
| **7. 边际成本** | API 消耗与 Token 费用是否会随用户乱点出现无限账单？ | 严格加设端侧限频、单用户每日 Quota 熔断与第三方调用支出预算告警。 |
| **8. 数据雷区** | 如果系统被黑或配置错误，会不会导致用户敏感数据泄漏让你惹上官司？ | 纯本地存储或完全不落盘处理；非必要绝不收集任何个人隐私信息。 |
| **9. AI 幻觉责任**| AI 输出错误是否会导致用户遭受商业合同违约或财务损失？ | 增加强制的 `[AI 生成内容需人工复核]` 确认门禁，避免完全自动化高危决策。 |
| **10. 虚荣指标**| 每天盯着 Google Analytics 页面浏览量，到底有几个人完成了关键目标动作？ | 看板只留一个核心指标：完成主任务的有效用户数。 |
| **11. 沉没执念**| 已经做了 3 个月没人用，你打算再做几个月才肯认输停手？ | 立即设定两周死线（Drop-dead date），未达指标直接归档封存。 |
