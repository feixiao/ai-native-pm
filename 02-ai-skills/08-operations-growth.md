# AI 辅助产品运营与增长闭环

"产品做完了，增长交给市场团队"——这句话正在杀死大量本可以自增长的产品。产品定义价值，运营兑现价值：**产品负责让用户"愿意用"，运营负责让用户"知道、留下、付费、带新人"**。

作为工程师转型的 PM，你不需要变成投放优化师，而是要用工程思维把运营做成**可持续运转的经营系统**：漏斗可度量、渠道可评分、实验有死线、护栏同步登记。借助 AI（Claude Code / Cursor + 对应 `pm-operations` Agent Skill），你可以把原本靠"感觉在涨"的运营动作，压缩成每周一次的结构化决策闭环。

> 对应 Agent Skill：`pm-operations`（Claude Code / Cursor 安装后自动激活）；指标口径与 SQL 分析联动 `pm-data-analyst`，触达合规护栏联动 `pm-security-compliance`。

## 一、 AARRR 全漏斗诊断：先定位漏损，再开药方

增长停滞时最忌讳"五个渠道同时加预算"。先用五层漏斗定位**唯一**最大漏损层，本周只打这一层：

```
                    ┌───────────────────────────────────────┐
                    │   Acquisition 获取                     │  ← CAC 与渠道来源质量（次留率）
                    └───────────────────┬───────────────────┘
                                        ▼
                    ┌───────────────────────────────────────┐
                    │   Activation 激活                     │  ← 到达 Aha Moment 的转化率与耗时
                    └───────────────────┬───────────────────┘
                                        ▼
                    ┌───────────────────────────────────────┐
                    │   Retention 留存                      │  ← Cohort 曲线形态（指数衰减 vs 平台期）
                    └───────────────────┬───────────────────┘
                                        ▼
                    ┌───────────────────────────────────────┐
                    │   Revenue 变现                        │  ← 付费转化率 / ARPU / LTV/CAC ≥ 3
                    └───────────────────┬───────────────────┘
                                        ▼
                    ┌───────────────────────────────────────┐
                    │   Referral 推荐                       │  ← K 因子 = 邀请数 × 邀请转化率，K ≥ 1 自增长
                    └───────────────────────────────────────┘
```

#### 提示词模板：五层漏斗诊断与单点打击方案
```markdown
你是 Staff 级增长运营策略师。我的产品现状如下：
- 所处阶段：[PMF 验证期 / 增长期 / 成熟期]
- 周新增用户：[N]，来源分布：[渠道 1 x% / 渠道 2 x% / ...]
- 激活（注册后 24h 内完成核心动作）：[x%]，平均耗时 [N 分钟]
- 次周留存：[x%]，第 4 周留存：[x%]
- 付费转化率：[x%]，ARPU：[$N]，获客成本 CAC：[$N]
- 自然推荐带来的新增占比：[x%]

请执行 AARRR 五层漏斗诊断：
1. 逐层计算转化率与环比变化，指出**唯一**的最大漏损层与判断依据（严禁同时开多个药方）；
2. 针对该漏损层给出 3 个候选动作，按「预期提升 / 实现成本 / 所需数据」评分排序；
3. 为选中的动作写一条进实验台账的四列记录：`假设（一句话）| 动作 | 观测指标与护栏 | 死线（≤14 天）`；
4. 明确指出本方案必须同步登记的反向护栏（卸载率 / 退订率 / 投诉率）。
```

## 二、 获客与分发渠道矩阵：Owned / Earned / Paid 三栏制

所有渠道动作必须落入三栏矩阵，严禁无主题的"先投了看看"：

| 栏位 | 渠道示例 | 纪律 |
|:---|:---|:---|
| **Owned 自有阵地** | 官网 SEO 页、应用商店 ASO 关键词与截图、私域社群、邮件列表 | 复利资产，长期经营，唯一可无限复利的渠道 |
| **Earned 内容口碑** | 技术博客、对比评测、教程视频 | 每篇必须锚定一个具体搜索意图，严禁无主题自嗨内容 |
| **Paid 付费投放** | 信息流、搜索广告、KOL 带货 | 必须给出预算上限与止损线；**无正向单位经济前预算上限为 0** |

#### 提示词模板：渠道矩阵设计与自发酵分发抓手
```markdown
我的产品是 [一句话描述 + 核心功能 + 目标用户]，已有资产：[官网 / 应用商店 / 社群 / 邮件列表 / 无]。

请为我设计 Owned / Earned / Paid 三栏渠道矩阵：
1. Owned 栏：列出可复利渠道及每个渠道的首个 30 天动作清单（含 ASO 关键词种子 / SEO 页面主题 / 社群冷启动 50 人方案）；
2. Earned 栏：给出 6 篇内容选题，每篇锚定一个真实搜索意图（写出目标搜索词），优先选"可长期被搜索到"的常青内容而非追热点；
3. **自发酵分发抓手（强制）**：设计至少 1 个产品内生的分享机制（可传播产出物：带来源水印的报告图 / 证书 / 战绩卡 / 协作邀请），写明触发点、分享物内容、回流落地页承接逻辑——严禁只靠外部投放；
4. Paid 栏：若单位经济已为正，给出首月预算、单渠道止损线与 K 因子测算口径；若未验证，直接输出"Paid 冻结，理由 = [单位经济数据]"。
```

## 三、 激活与 Onboarding：三步内到达 Aha Moment

激活是漏斗里最容易被忽视、却杠杆最高的一层。把 Onboarding 设计成**到达 Aha Moment 的最短路径**，而不是功能巡览：

1. 与 `pm-data-analyst` 对齐 Aha Moment 的行为阈值（如"首周完成 X 动作 ≥ N 次"）；
2. 设计 **3 步以内**的到达路径：每一步写明用户目标、引导文案原则、可跳过的分支；
3. **反模式警戒**：引导页每多一页，激活转化率通常折损一半——8 页功能巡览式的 Onboarding 直接判负。

#### 提示词模板：Onboarding 最短路径设计
```markdown
我的产品 Aha Moment 已被数据定义为：[行为阈值，如"完成第 3 次核心调用"]。当前新用户注册流程为：[现有步骤列表]。

请帮我重新设计 Onboarding：
1. 压缩到 ≤3 步到达 Aha Moment，每步输出：用户目标（一句话）、引导文案原则（不写最终文案，写约束）、可跳过分支与跳过后果；
2. 指出当前流程中每个"与 Aha 无关"的步骤及删除理由；
3. 给出激活转化率的基线假设与 14 天验证方案（分流比例、样本量测算、护栏指标）。
```

## 四、 留存与生命周期召回：Cohort 矩阵分段，触达带频控

留存先分诊：**新客留存**与**老客活跃**是两个不同的问题，严禁混诊。流失用户按生命周期分段，每段一套召回策略：

| 生命周期段 | 典型画像 | 召回策略 | 触达纪律 |
|:---|:---|:---|:---|
| 注册未激活 | 从未到达 Aha | 一次性引导重发 + 降低激活门槛 | 3 天内 ≤1 次 |
| 激活未复访 | 用过但没回来 | 价值回顾（你上次完成 X）| 7 天冷却后 1 次 |
| 复访未付费 | 活跃但未转化 | 付费墙场景化触发 | 进入变现实验（§五） |
| 付费流失 | 曾付费已退订 | 转 `pm-customer-success` 挽留流程 | 见其 Save Flow 频控 |

**召回触达（Push / 邮件 / 短信）必须写明频率上限与免打扰时段；连续 2 次未响应即进入冷却池，严禁轰炸。**

#### 提示词模板：Cohort 留存诊断与分段召回设计
```markdown
我上传了按注册周分组的 Cohort 留存矩阵（第 0-8 周）：[粘贴矩阵]。

请诊断：
1. 曲线形态是指数衰减、平台期还是持续下滑？分别意味着什么产品问题？
2. 将流失用户按生命周期四分段，给出每段的召回策略与触达频控（频率上限 / 免打扰时段 / 冷却池规则）；
3. 找到留存曲线上最大的单周断崖，用「端 / 渠道 / 版本 / 地域」四个维度给出下钻排查 SQL 思路（口径与 [05-data-analysis.md](./05-data-analysis.md) 的指标异动 4 层漏斗一致）；
4. 输出本周末的 30 分钟留存复盘清单。
```

## 五、 变现与定价实验：A/B 框架 + 毛利率后单位经济

定价不是拍脑袋，是实验。订阅制产品必须核算**毛利率后的单位经济**：

$$\text{单客净利} = \text{订阅收入} - \text{服务边际成本（API/云）} - \text{分摊获客成本}$$

#### 提示词模板：定价 A/B 实验设计与单位经济核算
```markdown
我的订阅产品当前：月付 $[N]，付费转化率 [x%]，ARPU $[N]，服务边际成本 $[N]/月，CAC $[N]，LTV（12 个月）估算 $[N]。

请设计定价实验：
1. 给出 2-3 档候选定价（含锚点价 / 年付折价 / 入门档），说明每档的心理账户逻辑；
2. 复用标准 A/B 框架：基线转化率、MDE、α=0.05 / Power=80%，计算每组最小样本量与实验天数（公式与 [05-data-analysis.md](./05-data-analysis.md) 场景 3 一致）；
3. 逐层拆解付费漏斗（付费墙曝光 → 点击 → 下单 → 支付成功），指出当前最大漏损点；
4. 核算各档定价下的单客净利与 LTV/CAC，$\text{LTV/CAC} < 3$ 的档直接淘汰并说明。
```

## 六、 病毒循环设计：分享动机必须来自用户自身收益

每个病毒动作四要素齐备：**触发点、分享物内容、回流落地页、K 因子测算口径**。

1. 分享动机必须来自**用户自身利益或社交收益**（炫耀 / 协作 / 利他），严禁强制分享解锁功能；
2. 回流落地页必须承接分享物上下文——回流用户看到的必须是"被分享的那个东西"，而非冷启动首页；
3. $\text{K} = \text{每用户邀请数} \times \text{邀请转化率}$，$\text{K} \ge 1$ 才具备自增长；K < 1 的"病毒功能"只是普通功能，如实标注。

#### 提示词模板：病毒循环设计与 K 因子测算
```markdown
我的产品核心使用场景是 [描述]，用户完成核心动作后会得到 [产出物形态]。

请设计病毒循环：
1. 从炫耀 / 协作 / 利他三类动机中选出最适合本产品的 1 类，说明理由；
2. 输出分享物设计（内容 / 视觉要点 / 来源水印位置）与触发时机；
3. 设计回流落地页：回流用户首屏必须承接分享物上下文，写出该页的 3 个模块与信息层级；
4. 给出 K 因子测算口径（分子分母各用什么埋点事件）与 14 天验证死线，护栏 = 分享被举报/投诉率。
```

## 七、 运营防坑铁律（渠道评分与实验台账）

1. **渠道必须进台账**：$\text{渠道分} = \frac{\text{周新增} \times \text{次留率}}{\text{单位成本（现金 + 个人小时数）}}$，每周五重算，连续 2 周垫底直接冻结；
2. **归因诚实原则**：自然流量暴涨先怀疑统计口径与外部事件（节日、热点、媒体报道），再谈渠道功劳，严禁把大盘红利记在自己账上；
3. **护栏同步登记**：任何增长实验必须同步登记反向护栏（卸载率、退订率、投诉率），护栏恶化超过 10% 立即停实验，无论主指标多好看；
4. **渠道依赖风险**：单一渠道占比 > 50% 必须给出第二渠道预案——平台算法一改就归零；
5. **投入产出诚实账**：算不过 LTV/CAC ≥ 3 的方案直接砍掉，"先投了看看"是运营第一大罪；
6. **产品-运营一致性**：落地页文案与分享物承诺必须与产品真实体验一致，夸大即负债，会反噬留存；
7. **独立开发者单兵纪律**：每周只运营 1 个主渠道；优先写可长期被搜索到的常青内容；把分享抓手做进产品本身（唯一可无限复利的分发资产）；周末只回答一个问题——"主渠道周新增与次留的环比方向"，连续 2 周恶化即换渠道或回产品找激活问题，严禁第三周惯性投入。
