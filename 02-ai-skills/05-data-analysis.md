# AI 辅助数据分析与实验决策

“感觉用户挺喜欢的”、“我觉得这个改版肯定能提升转化”——这是产品经理在汇报和决策时最忌讳的话。

作为有研发功底的 PM，你懂数据库表结构、懂日志格式、懂基本统计逻辑，这让你在数据分析上比普通文科 PM 快得多。借助 AI（Claude Code / ChatGPT Data Analysis / Cursor），你可以摆脱对数据团队排期取数的依赖，实现 **“自己提假设 → AI 秒级写 SQL/Python 跑数据 → AI 协助统计检验与归因 → 产出业务决策”** 的全自助闭环。

## 二、 五大高频数据分析场景与 AI 提示词模板

### 场景 1：自然语言生成复杂取数 SQL（漏斗与同期群留存）
不需要再花半小时手敲多层嵌套 `LEFT JOIN` 和窗口函数 `OVER (PARTITION BY ...)`，直接把表结构丢给 AI。

#### 提示词模板：生成漏斗与留存 SQL
```markdown
你是一位精通 ClickHouse / PostgreSQL / BigQuery 的资深数据分析师。
我们有以下两张核心埋点表：
1. `users` 表：`user_id`, `created_at` (注册时间), `plan_type` (free/pro/enterprise), `channel` (获客渠道)
2. `events` 表：`user_id`, `event_name`, `event_time`, `properties` (JSON，包含 `duration_ms`, `error_code`, `platform`)

请帮我编写两段高效、可直接运行的 SQL 查询（带清晰注释）：
1. **核心激活漏斗查询**：统计过去 30 天新注册用户中，在注册后 24 小时内依次完成 `signup_success` → `create_project` → `first_api_call` → `first_stream_success` 四个步骤的去重人数、单步转化率与整体转化率，并按 `channel` 分组对比。
2. **按周同期群留存表 (Weekly Cohort Retention)**：按用户注册所在的自然周分组（Cohort Week），计算他们在第 0 周、第 1 周、第 2 周……直到第 8 周仍然触发过 `first_stream_success` 事件的留存率百分比。
```

### 场景 2：上传 CSV / Excel 让 AI 直接做探索性数据分析 (EDA)
把脱敏后的业务导出表直接拖进 Claude 或 ChatGPT Code Interpreter，或者在本地让 Claude Code / Antigravity 直接写 Python 脚本跑分析。

#### 提示词模板：探索性归因分析与寻找“Aha Moment”
```markdown
我上传了一份过去 3 个月共 10,000 名新用户的行为汇总 CSV 文件，包含字段：`user_id`、`首周使用功能A次数`、`首周使用功能B次数`、`首周邀请队友人数`、`首周平均响应延迟ms`、`是否在第2个月继续留存(is_retained_m2)`、`是否转化为付费用户(is_paid)`。

请你编写并执行 Python 分析脚本，帮我回答以下核心产品问题：
1. **数据清洗与异常值检查**：是否存在极端离群值或缺失值？
2. **寻找产品的「Aha Moment（顿悟时刻）」**：
   - 计算首周各项行为特征与 `is_retained_m2`（次月留存）的相关性及提升度（Lift）。
   - 用决策树或逻辑回归找出一个最具解释力的阈值规则（例如：“首周完成 X 动作 ≥ N 次的用户，次月留存率从 15% 跃升至 68%”）。
3. **体验底线阈值分析**：当 `首周平均响应延迟ms` 超过多少毫秒时，用户的流失率会出现断崖式飙升？（帮我找到性能体验的拐点）
4. **可执行产品建议**：基于以上数据发现，建议我们在下个版本的「新手引导（Onboarding）」和「性能优化」上采取哪 3 个具体动作？
```

### 场景 3：A/B 测试方案设计与实验结果统计检验
很多 PM 做 A/B 测试看实验组转化率 12.5%、对照组 11.8%，就匆忙宣布“实验成功全量上线”，结果其实是随机波动（样本量不够，p-value > 0.05）。

#### 提示词模板：A/B 实验样本量测算与结果显著性判定
```markdown
你是一位精通实验设计的统计学专家与增长产品经理。

### 任务一：实验前样本量计算（若处于设计阶段）
我们准备对【新用户引导流程】进行 A/B 测试。
- 当前基线转化率（Baseline Conversion Rate）：`15.0%`
- 我们希望检测到的最小相对提升幅度（MDE, Minimum Detectable Effect）：相对提升 `10%`（即达到 `16.5%`）
- 显著性水平 $\alpha = 0.05$（双尾），统计功效 Power $(1-\beta) = 80\%$
- 当前该页面每日独立访客数为 `3,000 人/天`（50/50 分流）。
请帮我计算每组所需的最小样本量、实验至少需要跑多少天，并提醒实验期间需要注意的辛普森悖论与新奇效应（Novelty Effect）。

---

### 任务二：实验后结果评估与决策（若已有结果数据）
我们的 A/B 实验已经跑满 14 天，数据如下：
- **对照组 (Control)**：进入人数 `21,400`，转化人数 `3,210`，人均耗时 `45s`，客诉退订人数 `42`
- **实验组 (Variant)**：进入人数 `21,550`，转化人数 `3,491`，人均耗时 `52s`，客诉退订人数 `68`

请帮我进行严格的统计检验（Z-test / 卡方检验）：
1. 主指标（转化率）的提升是否具有统计显著性？给出 p-value 和 95% 置信区间。
2. 护栏指标（客诉退订率）的上升是否显著？
3. **综合决策建议**：综合主指标收益与护栏指标代价，建议「全量推全」、「针对特定人群灰度」还是「回滚重做」？为什么？
```

周一早上一看大盘：“上周日活（DAU）或支付转化率突然环比跌了 18%！”老板在群里问怎么回事，如何用结构化拆解法在 30 分钟内给出专业排查报告？

#### 提示词模板：指标异动结构化下钻诊断
```markdown
今天早上监控发现，我们产品的核心指标【指标名称，如：新用户首日音视频通话接通率 / 付费转化率】从平时的 `85%` 突然下跌到了 `71%`。

请作为资深数据产品经理，帮我生成一份【指标异动结构化排查 Checklist 與 SQL 下钻矩阵】，按以下 4 个层次由浅入深指导我快速定位根因：

1. **第一层：排除数据采集与埋点故障（Data Integrity）**
   - 检查是否发版导致埋点丢失、日志上报延迟、统计口径变更。
2. **第二层：外部周期性与宏观因素（External Factors）**
   - 节假日效应、特定地区网络运营商故障、云厂商故障、大促结束后的自然回落。
3. **第三层：多维交叉切片下钻（Dimension Slicing —— 核心！）**
   - **端与版本维度**：iOS vs Android vs Web？是不是刚刚灰度的 v2.4.1 新版本导致的？
   - **渠道与用户群维度**：是不是市场部新投放了一批低质量买量渠道流量，拉低了整体分母？
   - **地域与网络维度**：是不是某个特定国家/运营商节点的流失激增？
   - **漏斗子步骤拆解**：到底是“发起请求”少了，“信令握手”失败了，还是“首帧渲染”超时了？
4. **第四层：输出给老板的阶段性排查简报模板**（包含：已排除项、当前锁定嫌疑点、临时止血措施、预计修复时间）。
```

## 三、 产品经理的数据防坑铁律

1. **永远同时看“分子”和“分母”**：
   转化率突然提升了 20%，先别高兴——很有可能是顶部入口崩了导致进入漏斗的**分母暴跌**，只剩死忠老用户还在操作！
2. **相关性 $\neq$ 因果性 (Correlation is not Causation)**：
   数据显示“用过深色模式的用户留存率比不用深色模式的高 3 倍”，不代表你把所有新用户强行设成深色模式就能提升留存——因为只有重度高频用户才会有闲心去设置里开启深色模式。
3. **平均值会撒谎，多看分位数 (P50 / P90 / P99)**：
   这正是你的工程强项！无论是看用户使用时长、客单价还是加载耗时，永远不要只看平均值（Mean），一定要看中位数（P50）和长尾极值（P90/P99）。
