# AI 辅助市场调研与竞品分析

传统的行业调研与竞品拆解是极其消耗时间的苦力活：PM 需要翻阅几十份 PDF 研报、逐个注册体验竞品、去应用商店和社区扒拉上千条评论，往往花了一周才整理出一份静态 PPT。

借助 AI 工具链，你可以把 **“搜集信息与初步归类”的时间从 5 天压缩到 1 小时**，将 80% 的精力留给真正的战略判断：找到市场空白点与差异化切口。

---

## 一、 AI 市场与竞品调研工具矩阵

| 工具名称 | 核心定位与强项 | 适用环节 |
| :--- | :--- | :--- |
| **Perplexity / Gemini Deep Research** | 实时联网多轮深度搜索，自动交叉核对信源并附带真实引用链接 | 快速摸清陌生赛道规模、监管政策、竞品最新融资与动态 |
| **NotebookLM (Google)** | 零幻觉的私有文档知识库，支持一次导入数十份 PDF 研报、财报、官方文档 | 多份行业报告交叉对比、竞品 API/SDK 技术文档深度拆解 |
| **Claude 3.7 / GPT-4o** | 极强的结构化逻辑推理、框架套用（SWOT / 波特五力 / 商业画布）与长文合成 | 生成竞品功能对比矩阵、定价策略拆解、输出高管简报 |
| **Appbot / 爬虫 + LLM** | 批量抓取 G2、Capterra、App Store、GitHub Issues、Reddit 的用户真实评价 | 挖掘竞品被骂得最惨的“未满足痛点 (Unmet Needs)” |

---

## 二、 四步实战标准工作流 (SOP)

```
[Step 1: 广度扫描]          [Step 2: 深度喂料]          [Step 3: 痛点爆破]          [Step 4: 决策输出]
Perplexity / Deep Research ──► NotebookLM 导入文档/财报 ──► 抓取社区/GitHub差评聚类 ──► Claude 提炼差异化切口
(30分钟建立赛道全景图)         (交叉对比技术与产品边界)     (找到竞品最薄弱的软肋)       (输出 1-Page 战略建议)
```

### Step 1：30 分钟建立陌生赛道认知
不要一上来就陷入某个竞品的按钮细节。先用 Deep Research 或 Perplexity 搞清楚：这个市场有多大？正在增长还是萎缩？玩家分哪几个梯队？客户买单的决策链条是什么？

### Step 2：把竞品官方文档与财报丢进 NotebookLM
如果你做的是技术型产品（如音视频 PaaS、AI Infra、开发者工具），直接把 3 家核心竞品的**官方定价页、架构白皮书、SDK 接入文档、Release Notes** 保存为 PDF/Markdown 导入 NotebookLM，让它对比各家的技术指标边界与计费陷阱。

### Step 3：专门去挖竞品的“差评”与“迁移抱怨”
竞品宣传页写的都是优点，只有用户的差评里藏着你的机会。重点搜集：
* ToB/SaaS 软件：G2、Capterra、TrustRadius 上的 1-3 星评价；
* 开发者工具/Infra：GitHub Issues 高赞未解决 Bug、Hacker News / Reddit 上的吐槽帖（搜索关键词：`"[Competitor] alternative"`、`"[Competitor] pricing"`、`"[Competitor] latency issue"`）。

### Step 4：用结构化框架收敛为“我们的破局策略”
不要输出一份只有罗列没有结论的“百科全书”。最终报告必须回答：**我们凭什么赢？（Where to Play & How to Win）**

## 三、 即插即用提示词模板库 (Prompt Templates)

### 模板 1：快速摸清陌生行业全景（适用于 Perplexity / Deep Research）
```markdown
你是一位资深科技行业战略分析师。我正在调研【目标赛道，如：实时互动 AI 语音 Agent 基础设施 / WebRTC 云服务】领域。
请帮我检索最近 12 个月的最新公开数据与行业报告，按以下结构输出一份行业全景扫描：

1. **市场规模与增速**：当前 TAM/SAM 规模估算、年复合增长率（CAGR）及核心增长驱动力。
2. **产业链上下游拆解**：上游供应商（算力/网络/底层协议）、中游平台方、下游核心付费行业（前三大落地场景）。
3. **竞争格局分梯队**：
   - 第一梯队（霸主）：代表厂商、市场份额、核心护城河
   - 第二梯队（挑战者/垂直黑马）：代表厂商、差异化切入点
4. **客户采购核心决策因子（Key Buying Criteria）**：客户在选型时最看重的前 3 个指标是什么？
5. **最新技术与商业趋势**：过去半年出现的可能颠覆现有格局的新技术或新定价模式。

要求：所有关键数据必须附带来源链接；拒绝空洞套话，给出具体厂商名与量化指标。
```

### 模板 2：竞品多维深度拆解矩阵（适用于 Claude / GPT）
```markdown
我们要针对核心竞品【竞品A、竞品B、竞品C】做深度对比分析。我们的产品定位是【一句话描述你的产品及核心技术优势】。

请帮我构建一个 Markdown 多维对比矩阵，包含以下维度：
1. **核心价值主张 (UVP)** 與目标客群画像（SMB 中小企业 vs Enterprise 大客户）
2. **核心功能覆盖度**（区分基础必备功能 Must-have 与差异化亮点 Differentiators）
3. **技术指标与架构边界**（如：端到端延迟、并发上限、跨平台 SDK 支持度、私有化部署能力）
4. **开发者/用户接入体验 (Onboarding)**（跑通首个 Demo 所需步骤与门槛）
5. **商业化与定价策略 (Pricing Model)**（免费额度、按量计费阶梯、隐藏收费项）

在表格下方，请基于以上对比回答：
- 哪块细分市场目前处于“过度服务（价格虚高、功能臃肿）”状态？
- 哪块细分需求目前处于“服务不足（Underserved）”状态？
- 结合我们的技术优势，建议我们采取哪 2 个具体的差异化切入点？
```

### 模板 3：竞品定价策略与商业化逆向工程
```markdown
以下是竞品【竞品名称】官方定价页面的完整内容：
<pricing_page>
[粘贴竞品定价页文本或截图内容]
</pricing_page>

请作为 SaaS/PaaS 商业化定价专家，帮我逆向拆解其定价逻辑：
1. **价值度量单位 (Value Metric)**：它是按坐席（Seat）、按分钟数、按带宽峰值还是按 API 调用量收费？为什么选择这个指标？
2. **引流钩子 (Land Strategy)**：免费版或入门版卡住了哪个关键阈值，迫使用户在业务增长时必须升级？
3. **高毛利溢价点 (Expand Strategy)**：专业版与企业版之间拉开差价的核心功能是什么（如：SLA 保障、SSO 权限、专属集群、低延迟通道）？
4. **定价软肋**：哪类体量的客户在使用这套计费模式时会觉得“极度不划算/肉疼”？我们如何设计一套更有吸引力的价格结构去撬动这批客户？
```

### 模板 4：竞品用户差评与痛点爆破（挖掘 Unmet Needs）
```markdown
以下是我从 G2 / GitHub Issues / 社区论坛收集到的关于竞品【竞品名称】的 50 条真实用户抱怨与低分评价：
<user_complaints>
[粘贴收集到的用户差评、吐槽帖或 Issue 列表]
</user_complaints>

请帮我进行深度的痛点聚类与机会分析：
1. **高频痛点 Top 5 聚类**：按提及频次和情绪激烈程度排序，归纳出前 5 大核心槽点（每个槽点需附带 2 条代表性用户原话引用）。
2. **根因剖析**：利用工程与产品视角判断，竞品为什么迟迟没有解决这些痛点？（是因为历史架构包袱太重、破坏了其现有高毛利计费模式，还是单纯忽视了中小客户？）
3. **产品机会点转化**：如果我们把竞品的 Top 3 痛点变成我们的主打卖点，我们的产品 Slogan 和 MVP 核心特性应该怎么设计？
```

### 模板 5：新功能立项前的 SWOT 与波特五力压力测试
```markdown
我计划在现有产品中立项开发【新产品/新功能名称，如：基于 WebRTC 的低延迟 AI 实时陪练系统】，目标客户是【目标客群】。
目前市场上的主要替代方案有【竞品1、竞品2，以及人工替代方案】。

请不要顺着我的想法夸奖，而是扮演一位冷静苛刻的投资人/产品委员会评委，用 SWOT 模型和商业常识对我进行灵魂拷问：
1. **致命威胁**：大厂（如字节、腾讯、OpenAI）如果明天上线同名功能，我们是否会瞬间归零？我们的真实壁垒在哪？
2. **迁移成本（Switching Cost）**：客户目前已经在用替代方案，我们提供的价值是比现有方案好 20% 还是好 10 倍？如果只好了 20%，客户为什么要承担迁移风险换用我们？
3. **需要优先验证的 3 个生死假设（Leap-of-Faith Assumptions）**：在投入研发写代码之前，我应该用什么最低成本的方法（不写代码或极少代码）在 1 周内验证客户真的愿意为此买单？
```
